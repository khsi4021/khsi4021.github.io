### The problem

The capstone UAV needs a flight simulator that the controls, propulsion and aerodynamics leads can all plug into. The previous year's simulator could not be trusted: on the Boeing 747 benchmark, its short-period and Dutch-roll natural frequencies were 22 % and 65 % off the textbook values. A simulator is only useful if you can prove it integrates the equations you think it does.

### What we built

The simulator was a two-person effort, and I did the majority of the work.

- **A Simulink model generated from a script** (`build_Sim6DOF.m`), so the architecture is reviewable in git and merge conflicts in the `.slx` are impossible. The signal flow is: test inputs → flight control system → actuators → aerodynamics and propulsion; ISA atmosphere with optional Dryden wind → air data; gravity + aero + propulsion → 6-DOF Euler equations of motion. It uses a fixed-step `ode4` solver at 5 ms.
- **Aircraft data sets** that share one field layout: the B747 benchmark (Heffley & Jewell, NASA CR-2144, Condition 9: 40,000 ft, M 0.80) and a template for the capstone electric UAV, with turbofan and electric propulsion variants.
- **A two-level benchmark.** Level 1 linearises the *full nonlinear* Simulink model about trim and compares its eigenvalues with an analytic linear model built from the same derivatives, and with Etkin's textbook values. Level 2 overlays elevator and rudder doublet responses.

### Why two references

The benchmark separates two kinds of error:

- **Simulator vs analytic model, same data.** This isolates simulator bugs: frames, signs, integration.
- **Analytic model vs Etkin's textbook.** This isolates data differences.

The pass criterion we proposed for the Test Readiness Review applies to the first comparison, with the atmosphere frozen so both models share the same assumptions:

<Equation tex={String.raw`\frac{|\omega_{n,\text{sim}} - \omega_{n,\text{analytic}}|}{\omega_{n,\text{analytic}}} < 2\%, \qquad |\zeta_\text{sim} - \zeta_\text{analytic}| < 0.01`} />

### Linearising the nonlinear model

`linearize` extracts the state matrix A of the whole Simulink model. Its eigenvalues include actuator, filter and engine poles, so each physical mode is identified by **eigenvector content**: velocity states are scaled by 1/V, and the longitudinal (u, w, q, θ) and lateral (v, p, r, φ) parts of each eigenvector are compared. Complex pairs and real roots are then ordered to give short period, phugoid, Dutch roll, roll subsidence and spiral.

### A sign that matters

The body frame is the stability-axis frame of the reference condition. Heffley gives the inertias and lateral derivatives there, so no inertia rotation is needed. The Aerospace Blockset 6-DOF block expects the inertia *tensor*, whose off-diagonal term is the **negative** of the product of inertia I<sub>xz</sub>:

<Equation tex={String.raw`J = \begin{bmatrix} I_x & 0 & -I_{xz} \\ 0 & I_y & 0 \\ -I_{xz} & 0 & I_z \end{bmatrix}`} />

Getting this sign wrong makes the Dutch roll go unstable.

### Ready for the controls team

The flight control system block has an open-loop mode (for benchmarking) and a stability-augmentation mode (pitch, roll and yaw rate dampers). The controls team's outer loops plug in there. The UAV template warns about OpenVSP's x-aft/z-up frame, which caused last year's control-surface bug, and converts positions with a helper before they enter the model.

<Callout tone="honest" title="Where it doesn't match the textbook">
Against Etkin, the short period, Dutch roll and roll subsidence agree within about 0.6 % in ω<sub>n</sub>. Three differences remain, and none is a simulator error:
- **Spiral mode: 84 % off.** Etkin's spiral target is unverified, and the analytic model built from the same derivatives gives the same root as the simulator.
- **ISA phugoid: 27 % off.** This is a real density-gradient effect. With the atmosphere frozen, the phugoid is within 5 %.
- **Dutch-roll damping:** ζ = 0.047 against Etkin's 0.035, again matching the analytic model built from the same data.
</Callout>

<TabPanel id="reflection">

### Limitations

- The aerodynamics are a **derivative model** about one flight condition. That is right for a benchmark, but not for large excursions.
- The capstone UAV data set is still a **placeholder** until the team's OpenVSP stability derivatives, mass properties and propulsion data arrive.
- The analytic doublet responses neglect actuator dynamics, so part of the 0.5–0.9 % time-domain difference is the actuators, not the simulator.

### Next steps

Load the team's VSPAERO derivatives and mass properties into the UAV data set, close the controls team's outer loops in the FCS block, and add a validation case with published UAV flight data.

### What I learned

Build verification into the architecture. Generating the model from a script made every change reviewable, and comparing against an analytic model built from *the same numbers* turned "does it look right?" into a pass/fail test. Separating simulator error from data error was the step the previous simulator was missing.
